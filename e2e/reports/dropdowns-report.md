## Test Infrastructure Notes

### Scroll-race finding (resolved in test layer)

During test authoring, a subtle race was discovered:

**Root cause:** `RowActionMenu` registers `window.addEventListener('scroll', close, true)`
(capture phase) after `setOpen(true)`. When Playwright's `trigger.click()` needed to
scroll the trigger into view, Chromium fired two post-click scroll events ~9 ms after
the click. These events hit the capture listener while `open=true`, immediately closing
the portal before the test's `waitForSelector` could detect it.

**Test fix:** `scrollIntoViewIfNeeded()` is called on each trigger locator before
`trigger.click()`. The pre-scroll fires with `open=false` (no listener registered);
the subsequent click fires with the element already in-viewport; no further scroll
events are generated by Playwright.

**App behaviour note (not fixed per task constraints):** The capture-phase scroll
listener is intentional for closing the menu on user scroll, but it also fires on
programmatic scroll events (Playwright post-click adjustments). This is a known
interaction between the app's scroll-close logic and Playwright's scroll-to-view.
